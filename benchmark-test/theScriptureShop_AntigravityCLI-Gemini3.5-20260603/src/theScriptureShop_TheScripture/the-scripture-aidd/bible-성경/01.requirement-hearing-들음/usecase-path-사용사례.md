## 유스케이스 상세

### UC-001: 성경 목록 조회

| 항목 | 내용 |
|:---|:---|
| UC-ID | UC-001 |
| 유스케이스명 | 성경 목록 조회 |
| 행위자 | ACT-001 (비회원 사용자) |
| 연결 REQ | REQ-001, FR-001 |
| 전제 조건 | 사용자가 쇼핑몰 메인 화면에 접속함 |
| 사후 조건 | 10개의 성경 번역본 목록이 화면에 정상 표시됨 |

**정상 경로 (Main Path — 좁은 길):**
1. 사용자가 메인 페이지에 접속한다.
2. 시스템이 SQLite DB에서 사전에 등록된 10개의 성경 목록(표지, 번역본 이름, 설명)을 조회한다.
3. 시스템이 카드 레이아웃으로 10개의 성경 상품 정보를 표시한다.

**예외 경로 (Exception Path — 넓은 길):**
- E1. DB 연결 실패 또는 데이터 없음 → "성경 목록을 불러올 수 없습니다. 시스템 관리자에게 문의하세요." 경고 문구 표시.

### UC-002: 장바구니 관리

| 항목 | 내용 |
|:---|:---|
| UC-ID | UC-002 |
| 유스케이스명 | 장바구니 관리 |
| 행위자 | ACT-001 (비회원 사용자) |
| 연결 REQ | REQ-002, FR-002, FR-003 |
| 전제 조건 | 사용자가 메인 화면에서 성경 목록을 조회함 |
| 사후 조건 | 사용자의 장바구니 정보(성경 및 수량)가 임시 저장 및 갱신됨 |

**정상 경로 (Main Path — 좁은 길):**
1. 사용자가 특정 성경 카드에서 `[장바구니 담기]` 버튼을 클릭한다.
2. 시스템이 해당 항목을 세션 장바구니에 추가하고, 장바구니 요약(수량 등)을 업데이트한다.
3. 사용자가 장바구니 화면으로 진입하여 목록을 확인한다.
4. 사용자가 특정 성경의 수량을 변경(예: 1개 -> 2개)하거나 `[삭제]` 버튼을 클릭한다.
5. 시스템이 변경 사항을 세션 장바구니에 반영하고 화면을 비동기(HTMX)로 갱신한다.

**대안 경로 (Alternate Path):**
- 1a. 이미 장바구니에 담긴 성경인 경우 → 시스템이 수량을 1 증가시킨다.

**예외 경로 (Exception Path):**
- E1. 수량을 0 이하로 변경 시도 → 시스템이 최소 수량은 1개임을 안내하거나 자동으로 항목을 삭제 처리한다.

### UC-003: 신앙 고백 및 주문 작성

| 항목 | 내용 |
|:---|:---|
| UC-ID | UC-003 |
| 유스케이스명 | 신앙 고백 및 주문 작성 |
| 행위자 | ACT-001 (비회원 사용자) |
| 연결 REQ | REQ-003, FR-004, FR-005, FR-006 |
| 전제 조건 | 사용자가 장바구니에 성경을 1개 이상 담고 장바구니 화면에 있음 |
| 사후 조건 | 주문이 성공적으로 DB에 등록되고 주문번호가 화면에 표시됨 |

**정상 경로 (Main Path — 좁은 길):**
1. 사용자가 장바구니 화면에서 `[주문하기]` 버튼을 클릭한다.
2. 시스템이 비회원 배송 주소 입력 폼과 하단의 신앙 고백문(체크박스) 및 `[믿는다]` 버튼을 표시한다.
3. 사용자가 이름, 연락처, 주소를 입력한다.
4. 사용자가 신앙 고백문 체크박스를 선택하여 동의한다.
5. 사용자가 `[믿는다]` 버튼을 클릭한다.
6. 시스템이 주소 유효성과 체크박스 상태를 검증한다.
7. 시스템이 고유 주문번호(예: S-YYYYMMDD-XXXX)를 생성하고 DB에 '발송 대기' 상태로 주문을 저장한다. (신앙 고백 동의 여부 및 일시 기록)
8. 시스템이 장바구니를 비우고 주문 완료 화면을 표시하며 생성된 '주문번호'를 명확하게 렌더링한다.

**예외 경로 (Exception Path):**
- E1. 주소 폼 필수 값 누락 → 시스템이 "필수 정보를 입력해주세요." 메시지를 표시하고 주문 접수를 중단한다.
- E2. 신앙 고백 체크박스 해제 상태에서 `[믿는다]` 클릭 → 시스템이 "예수님을 구원자로 고백하고 동의하셔야 성경을 주문하실 수 있습니다." 경고를 표시하고 주문 접수를 중단한다.

### UC-004: 비회원 배송 조회

| 항목 | 내용 |
|:---|:---|
| UC-ID | UC-004 |
| 유스케이스명 | 비회원 배송 조회 |
| 행위자 | ACT-001 (비회원 사용자) |
| 연결 REQ | REQ-004, FR-007 |
| 전제 조건 | 사용자가 메인 화면에 접속함 |
| 사후 조건 | 사용자의 주문 상태 및 송장번호가 화면에 렌더링됨 |

**정상 경로 (Main Path — 좁은 길):**
1. 사용자가 메인 페이지 상단의 `[배송 조회]` 버튼을 클릭한다.
2. 시스템이 주문번호를 입력할 수 있는 팝업 모달 또는 페이지를 표시한다.
3. 사용자가 발급받은 '주문번호'를 입력하고 `[조회]`를 클릭한다.
4. 시스템이 DB에서 해당 주문번호를 조회한다.
5. 시스템이 주문 상세(주문 상품, 수량, 주소, 처리 상태) 및 송장번호(발송 완료 상태인 경우)를 표시한다.

**예외 경로 (Exception Path):**
- E1. 존재하지 않는 주문번호 입력 → "일치하는 주문 정보가 없습니다. 주문번호를 다시 확인해 주세요." 메시지 표시.

### UC-005: 관리자 로그인/로그아웃

| 항목 | 내용 |
|:---|:---|
| UC-ID | UC-005 |
| 유스케이스명 | 관리자 로그인/로그아웃 |
| 행위자 | ACT-002 (관리자) |
| 연결 REQ | REQ-005, FR-008 |
| 전제 조건 | 관리자가 `/admin` 경로로 접속함 |
| 사후 조건 | 세션 인증이 처리되어 관리자 대시보드 접근 권한이 부여되거나 소멸됨 |

**정상 경로 (Main Path — 좁은 길):**
1. 관리자가 브라우저에 `/admin`을 입력하여 접근한다.
2. 시스템이 관리자 로그인 폼을 제공한다.
3. 관리자가 아이디 `admin`, 패스워드 `admin`을 입력하고 `[로그인]`을 클릭한다.
4. 시스템이 계정 정보를 확인하고 세션에 인증 플래그를 저장한다.
5. 시스템이 관리자 전용 대시보드로 이동시킨다.
6. 관리자가 대시보드 상단의 `[로그아웃]`을 클릭하면, 시스템이 세션을 만료시키고 로그인 화면으로 리다이렉트한다.

**예외 경로 (Exception Path):**
- E1. 잘못된 계정 정보 입력 → "아이디 또는 비밀번호가 일치하지 않습니다." 에러 표시.
- E2. 인증되지 않은 사용자가 관리자 대시보드 경로로 직접 접근 시도 → 시스템이 즉시 `/admin` 로그인 화면으로 리다이렉트 처리함.

### UC-006: 주문 목록 및 상세 조회

| 항목 | 내용 |
|:---|:---|
| UC-ID | UC-006 |
| 유스케이스명 | 주문 목록 및 상세 조회 |
| 행위자 | ACT-002 (관리자) |
| 연결 REQ | REQ-005, FR-009, FR-010 |
| 전제 조건 | 관리자가 로그인 상태로 관리자 대시보드에 있음 |
| 사후 조건 | 상태별 주문 목록과 주문자의 신앙 고백 합격 내역을 조회함 |

**정상 경로 (Main Path — 좁은 길):**
1. 관리자가 대시보드에서 주문 목록을 상태(발송 대기 / 발송 완료) 탭이나 필터로 조회한다.
2. 시스템이 선택된 상태에 해당하는 주문들을 리스트로 렌더링한다.
3. 관리자가 특정 주문을 클릭하여 상세 정보를 조회한다.
4. 시스템이 주문자의 정보, 주소, 주문 상품 수량과 함께, 사용자가 동의한 신앙 고백 문구 및 동의 시각을 명확하게 표시한다.

### UC-007: 송장 등록 및 발송 처리

| 항목 | 내용 |
|:---|:---|
| UC-ID | UC-007 |
| 유스케이스명 | 송장 등록 및 발송 처리 |
| 행위자 | ACT-002 (관리자) |
| 연결 REQ | REQ-005, FR-011 |
| 전제 조건 | 관리자가 '발송 대기' 주문의 상세 정보를 조회 중임 |
| 사후 조건 | 주문 상태가 '발송 완료'로 업데이트되고 송장번호가 저장됨 |

**정상 경로 (Main Path — 좁은 길):**
1. 관리자가 주문 상세 화면의 송장번호 입력 란에 8자리 숫자(예: 12345678)를 입력한다.
2. 관리자가 `[발송처리]` 버튼을 클릭한다.
3. 시스템이 입력된 송장번호가 8자리 숫자인지 유효성을 검증한다.
4. 시스템이 주문 상태를 '발송 완료'로 갱신하고 송장번호를 저장한다.
5. 시스템이 갱신된 주문 정보(발송 완료 상태)를 화면에 반영한다.

**예외 경로 (Exception Path):**
- E1. 송장번호가 8자리가 아니거나 숫자가 아닌 문자가 포함됨 → 시스템이 "송장번호는 반드시 8자리 숫자여야 합니다." 메시지를 표시하고 처리를 거부한다.
